# 과업 원장 (task-ledger) — 사용법

`target/tasks/` 를 스캔해 한 그룹의 과업 상태를 결정론으로 산출하고, WE-ADP Developer 화면이 읽는
`ledger.json` 한 장을 만든다.

- 생성기 `scripts/task-ledger.cjs`
- 출력 계약 `scripts/task-ledger.schema.json` ← **필드 정본은 이 파일이다.** 이 문서는 필드표를 재작성하지 않는다.
- 화면 `web/developer.html`
- 수신 어댑터 `scripts/adapters/`

**이 레포와 하네스의 관계** — 이 레포는 스캔 대상을 갖고 있지 않다. 과업 원문은 JEX 하네스
워킹카피의 `target/tasks/` 에 있고, 생성기는 `--root` 로 그 하네스를 가리켜 읽는다. 하네스 소유
도구 3종(`task-paths.cjs`·`hooks/lib/registry.js`·`scan-publish.sh`)은 **정본이 하네스에 있으므로
여기로 복제하지 않는다** — 사본을 두면 반드시 어긋난다.

**무엇이 아닌가** — 작업 관리 도구가 아니다. 사람이 상태를 입력하는 곳이 없다. 개발자가 평소처럼
`/dev-plan`·`/qa-test`·`/code-review` 를 돌리면 산출물 파일이 생기고, **그 파일의 실재가 곧 상태**다.

**용어** — WE-ADP 표준 용어를 쓴다. 개발 지시 문서는 **TRD**(Technical Requirements Document)다.
컨셉 목업의 `TDD` 표기는 쓰지 않는다.

## 빠른 시작

```bash
# 0. 이 레포를 하네스 워킹카피 안에 둔다 (권장: <하네스>/target/developer-repo/)
#    target/ 은 하네스가 추적하지 않으므로 두 레포가 섞이지 않는다.

# 1. 원장 생성 — --root 는 하네스 루트(.claude/scripts/task-paths.cjs 가 있는 폴더)
node scripts/task-ledger.cjs --root ../../ --group BIZ_ZEROPAY
#    → web/ledger.json

# 2. 화면 열기
node scripts/serve.cjs            # 기본 8080 · 브라우저 자동 실행
node scripts/serve.cjs --port 9000 --no-open
```

**`file://` 로 직접 열면 화면이 빈다.** 브라우저가 `ledger.json` 의 `fetch` 를 막는다(CORS).
화면이나 원장이 잘못된 것이 아니므로 `serve.cjs` 로 띄워서 본다.

`--root` 를 생략하면 스크립트 위치와 현재 폴더에서 위로 올라가며 하네스를 찾고,
`JEX_HARNESS_ROOT` 환경변수도 본다. 찾지 못하면 `exit 2` 로 끝난다 — 추측하지 않는다.

## 생성

```
node scripts/task-ledger.cjs [--root {하네스루트}] [--group {그룹}] [--out {경로}]
                            [--stale-days N] [--json] [--quiet]
```

| 인자 | 기본값 | 뜻 |
|---|---|---|
| `--root` | 자동 탐지 | 스캔할 하네스 루트. 틀리면 `exit 2` — 다른 곳으로 대체하지 않는다 |
| `--group` | `BIZ_ZEROPAY` | 대상 그룹. `_intake.json.project` 와 대조한다 |
| `--out` | `web/ledger.json` | 산출 경로 (**현재 폴더 기준**) |
| `--stale-days` | `14` | 무변경 판정 임계값 (아래 14일 규칙) |
| `--json` | — | 파일 대신 stdout 으로 원장 JSON |
| `--quiet` | — | 콘솔 요약 생략 |

| exit | 뜻 |
|---|---|
| 0 | 생성 성공 |
| 1 | 대상 그룹에 과업 0건 |
| 2 | 사용오류 **또는 출력이 계약을 어김** |

계약을 어기면 **파일을 쓰지 않는다**. 반쪽 원장이 화면에 실려 실패가 감춰지는 것을 막는다.

> 성능 — 경로 해석은 `task-paths.cjs` 에 위임하므로 과업당 1회 프로세스를 띄운다.
> 그래서 **그룹 필터를 먼저** 한다. 전체(179건)에 부르면 10초가 든다. 이 순서를 바꾸지 말 것.

## 상태 판정

상태는 **진입 단계(`_intake.json.entry`)마다 경로가 다르다.** 단일 규칙을 쓰면 계획서가 생기지 않는
진입 단계의 과업이 영원히 `접수` 에 머문다(실측: 178건 중 93건이 그랬다).

| 진입 단계 | 경로 | 근거 |
|---|---|---|
| `interview` · `plan` | 접수 → 개발중 → 리뷰중 → 완료 | `plan/dev_plan.md` → `test/test_result.md` → `target/reviews/{과업}.json` |
| `direct` | 접수 → 리뷰중 → 완료 | 계획서 단계를 건너뛴다 |
| `investigate` · `ops` · `harness` | 접수 → 완료 | 산출물 실재 또는 14일 규칙 |

상태는 **역행하지 않는다** — 여러 근거가 동시에 성립하면 가장 진행된 단계를 채택한다.

### 14일 규칙 (`investigate`·`ops`·`harness` 한정)

조사·운영 과업은 결과가 대화와 메모리에만 남는 것이 정상이라 파일로 완료를 알 수 없다.

| 조건 | 상태 | `statusInferred` |
|---|---|---|
| 리뷰 판정 파일(`target/reviews/{과업}.json`) 있음 | 완료 | `false` |
| 그 밖의 산출물만 있음 | 완료 | **`true`** — '무언가 만들어졌다'일 뿐 완료 표시가 아니다 |
| 산출물 없음 + 최종 변경 14일 이내 | 개발중 | `false` |
| 산출물 없음 + 14일 이상 무변경 | 완료 | **`true`** |

### `statusInferred` 를 읽는 법

`true` 는 **"근거가 무변경 기간뿐"** 이라는 뜻이다. 확인된 완료가 아니다. 화면은 이 값을 점선 뱃지와
물음표로 구분해 보여준다. 사람이 원장이 아니라 **실제 과업을 보고** 닫아야 한다.

## 기존 도구와의 관계

`wiki-summary.cjs` 도 상태를 판정한다. **어휘가 다른 것은 의도다** — 세는 축이 다르다.

| `wiki-summary.cjs` (발행 상태 5택) | 원장 (개발 진행 4택) | 같은 근거 |
|---|---|---|
| (근거 없음) | 접수 | — |
| 계획완료 | 개발중 | `plan/dev_plan.md` |
| 개발완료 | 리뷰중 | `test/test_result.md` |
| 배포요청 | 완료 | `release/deploy_manifest.md` |
| — | 완료 | `target/reviews/{과업}.json` ← wiki 는 보지 않는다 |
| 커밋완료 · 배포완료 | — | 외부 사실이라 파일로 유도 불가 |

**공유 모듈로 묶지 않는다.** 어휘가 다르므로 계약 공유가 아니고, 묶으면 한쪽을 고칠 때 다른 쪽이
조용히 바뀐다. 원장은 `wiki-summary.cjs` 를 **읽지도 수정하지도 않는다**(변경분 0줄).

두 도구가 같은 근거에서 반대를 가리키는 일은 없다(대조 실측: 역행 0건).

## 화면 열기

화면은 데이터를 담지 않는다. 같은 폴더의 `ledger.json` 을 `fetch` 로 읽는다.

```bash
cd target/developer && python -m http.server 8080
```

| 증상 | 원인 | 조치 |
|---|---|---|
| "로컬 서버로 열어야 합니다" | `file://` 에서 `fetch` 가 CORS 로 막힘 | 위 명령으로 열기 |
| "원장이 없습니다" | `ledger.json` 부재 | 생성 명령 먼저 |
| "원장이 손상됐습니다" | JSON 파싱 실패 | 재생성 |
| "계약 버전이 다릅니다" | `meta.schemaVersion` 이 화면 허용 목록 밖 | 화면과 원장을 함께 맞춤 |

메뉴는 표준 8개다. 데이터가 없어도 **메뉴를 숨기지 않는다** — 권한으로 메뉴를 감추는 것을 표준이 금지한다.
운영현황·사용량분석·보안검토는 Developer 기능이 아니라 **Admin 외부 링크**다.

## 수신 어댑터 교체

**전송 방식은 합의됐고(2026-09-22) 요청서 형식은 아직이다.** 그래서 수신부를 어댑터로 격리했다.

```
Builder 레포  ──push──▶  저장소 레포  ──clone/pull──▶  Developer
                github.com/beple-dev-1/we-adp-repository-test
```

**계약** — 어댑터는 `{ name, load }` 를 내보내고, `load({group, root})` 가 아래 형태의 배열을 돌려준다.

```
{ requestId, group, type: 'FRD'|'SRT', title, status, receivedAt, linkedTaskIds: [] }
```

**추가 절차** — `scripts/adapters/` 에 `.cjs` 파일 하나를 더 놓는다. 본체·스키마·화면은
바뀌지 않는다. 규약 3가지:

- 본체를 `require` 하지 않는다 (의존 방향은 본체 → 어댑터 단방향).
- 그룹 필터는 본체가 한다. 어댑터는 읽은 것을 그대로 준다.
- 동기 함수다. 본체가 동기 스캔이라 async 를 섞으면 호출부가 오염된다.

> **이 폴더는 신뢰 경계다.** 놓인 파일이 `require` 로 그대로 실행된다.
> 어댑터 추가는 하네스 파일 수정 원칙(사용자 확인)을 따른다.

`requestId` 가 겹치면 **먼저 로드된 어댑터가 이긴다**.

### 현재 어댑터 2종

| 어댑터 | 읽는 곳 | 상태 |
|---|---|---|
| `requests-local.cjs` | `target/requests/*.json` | 동작. 손으로 넣어도 되므로 규격 확정 전에도 화면이 돈다 |
| `adp-repository.cjs` | 저장소 레포 clone (`target/adp-repository`, `ADP_REPOSITORY_DIR` 로 덮음) | **골격만 — 요청서 0건** |

### `adp-repository` 가 0건인 이유

전송 방식만 합의됐고 **실어 보낼 요청서 형식이 정해지지 않았다.** 2026-09-22 저장소 레포
전수 실측 — `FRD`·`SRT`·`요청서` 문구가 하나도 없다. 들어 있는 것은 이렇다.

| 내용 | 건수 |
|---|---|
| `index.json` 화면 | 454 (BPY 118 · HIT 123 · BPG 79 · MCH 62 · EXW 55 · MGC 17) |
| 페이지 명세 `.md` | 55 (전부 EXW) — `과업:` 필드는 **55건 전부 비어 있음** |
| `화면유형` | 454건 전부 `미분류` |

화면명세를 요청서로 바꿔 세는 것은 지어내는 일이라 하지 않는다. Builder 가 형식을 정해
push 하면 `parseRequests()` 안만 채운다 — 경로 해석·레포 판별·그룹 매핑·경고는 이미 있다.

어댑터의 동작 4가지: clone 없음 → 조용히 0건 · `manifest.json` 못 읽음 → 경고 ·
toolchain 표식 없음 → 경고 · 레포는 있는데 요청서 0건 → 경고(지금 상태).
**조용한 0건과 못 읽은 0건을 가르는 것**이 이 경고들의 값이다.

### system → 그룹 매핑

저장소 레포의 `system` 은 Builder 의 시스템 구분이고, 원장의 `group` 은 과업의 프로젝트다.
축이 달라 옮겨야 한다. **근거가 있는 것만 적는다** — 짐작으로 채우면 남의 그룹 요청이
수신함에 섞인다.

| system | label | 그룹 | 근거 |
|---|---|---|---|
| `EXW` | 외부제공 웹뷰 | `BIZ_ZEROPAY` | 페이지 명세가 `brnd_webview_gift_list_view.jsp` 를 원본으로 지목 |
| `BPG` | 비플PG | `BPPAY_PG` | `manifest.json` 의 label |
| `BPY` | 비플페이 앱 | `BIZ_ZEROPAY` | 사용자 확정 (2026-09-22) |
| `HIT` | 힛플러스 | `BIZ_ZEROPAY` | 사용자 확정 (2026-09-22) |
| `MCH` | 가맹점관리 | `AFLT` | 사용자 확정 (2026-09-22) |
| `MGC` | 모바일상품권 | — | **보류** — 사용자가 빈 값으로 두기로 정함 |

## 내보내기 (선택)

기본 동작에서는 **아무것도 외부로 나가지 않는다.** 원장·화면 모두 `target/` 에 머물며 이 경로는
어느 레포에도 추적되지 않는다. 공유가 필요할 때만 아래를 명시 호출한다.

```
node scripts/task-ledger.cjs export [--root ...] [--file ...] [--dest {경로}] [--dry-run]
```

| 단계 | 동작 | 실패 시 |
|---|---|---|
| 1 | 실재·파싱·계약 검증 | exit 2 — 내보내지 않음 |
| 2 | `scan-publish.sh` 발행 스캔 | exit≠0 이면 즉시 중단 (fail-closed) |
| 3 | `--dry-run` 이면 종료 | — |
| 4 | `--dest` 로 복사 | 권한·경로 오류를 그대로 노출 |

- **우회 인자가 없다** — `--force`·`--skip-scan` 를 만들지 않았다. fail-closed 의 값은 예외가 없다는 데 있다.
- **히트의 매칭 값은 찍지 않는다** — 파일·패턴·줄번호만. 스캔 로그가 시크릿 사본이 되면 안 된다.
- **커밋·push 는 하지 않는다** — 복사까지만 하고 사람이 커밋한다. 권한 실패를 스크립트가 삼키지 않게 하기 위함이다.
- **진단 문자열에서 파일 경로를 벗긴다** — 예외 메시지는 절대경로(사용자명·머신 구조)를 담는다. 생성기가 `scrub()` 으로 지우고, 스키마가 `diagnostics` 문자열에 경로 패턴을 금지해 이중으로 막는다. `scan-publish.sh` 패턴에는 경로 축이 없어 게이트가 대신 잡아 주지 못한다.

### 게이트가 막는 것과 못 막는 것

| 막는다 | 못 막는다 |
|---|---|
| 시크릿·인증키 | **사업 정보** — 과업 제목의 고객사명 |
| 개인정보(PII) | 업무 맥락에서만 드러나는 민감도 |
| 내부 IP·호스트 | |

## 한계

이 표를 지우지 말 것. 빼고 "잘 동작함" 만 남기면 다음 사람이 추정 판정을 사실로 믿는다.

| 한계 | 내용 |
|---|---|
| TRD 상태 | **과업 상태에서 유도한 값**이다. 페이즈 문서에 기계가 읽을 완료 표시가 없어(실측 10건 전수) 한 과업의 TRD 가 전부 같은 상태로 보인다. 페이즈 단위 진행도가 아니다 |
| 14일 추정 | `statusInferred=true` 는 근거가 무변경 기간뿐이다. 사람이 닫아야 한다 |
| `direct` 비대칭 | `direct` 진입에는 14일 규칙이 없어 오래 방치된 과업이 `접수` 로 남는다. 브리프 결정을 그대로 따른 것이며 임의로 확대하지 않았다 |
| 진척률 | 시간이 아니라 **구성물 완료 비율**이다(요청서→과업, 과업→TRD). 과업 다수가 당일 종료라 시간 기반 진척은 값이 나오지 않는다 |
| 스캐너 | 시크릿·PII·내부IP 는 잡지만 **고객사명 같은 사업 정보는 못 잡는다** |
| 스캐너 패턴 범위 | 게이트는 `scan-publish.sh` 의 패턴 집합이 전부다. **그 집합에 없는 형식은 통과한다** — 실측(2026-09-22) `password=`·사설 IP 는 차단, AWS 액세스키 형식(`AKIA…`)은 통과. 게이트 통과가 "안전 확인"이 아니다 |
| 공개 레포 | 내보내기 대상 레포가 PUBLIC 이다. "그대로 올린다" 는 사용자 결정에 따른다. PRIVATE 로 바뀌면 이 항목은 해소된다 |
| 그룹 범위 | 1차는 `BIZ_ZEROPAY` 하나다. `--group` 으로 넓힐 수 있으나 표준이 **그룹 추가·변경 시 워킹그룹 공유**를 요구한다 |
| 담당자 | `git config user.name` = **원장을 만든 사람**이지 과업 수행자가 아니다. 이름 대신 이메일을 설정한 환경은 값을 버린다 |
| 실명 노출 | `generatedBy`·`owner` 에 **실명**이 실린다. `scan-publish.sh` 는 이메일은 막지만 실명은 막지 않는다 — 공개 레포로 내보내면 실명이 함께 나간다 |
| 레거시 과업 | `adhoc_*`·슬러그·3자리 등 cut-over 이전 산출물은 스캔하지 않는다 |
| 마감일 | 하네스 과업에 마감일이 없다. 간트 막대는 채번일~최종변경일이며 계획선을 그리지 않는다 |
| 성능 | 경로 해석을 한 프로세스에 모아 181건 49초 → 0.6초가 됐다. 다만 `task-paths.cjs` 가 **main 가드 없는 순수 CLI** 라는 구조에 기대고 있다. 하네스가 그 구조를 바꾸면 자체검사가 잡아 느린 spawn 길로 되돌아가고 경고를 남긴다 — 조용히 틀리지는 않는다 |
| 신선도 | 원장은 사람이 만들 때만 갱신된다. 화면 상단이 생성 시각을 상시 표시하고 6시간을 넘기면 다시 만들라고 말한다. **자동 갱신은 없다** |
| 알림 읽음 | **이 브라우저에만** 남는다(`localStorage`). 원장은 스캔 생성형이라 사람이 누른 흔적을 담을 자리가 없고 화면도 정적 파일이라 쓰기를 받을 서버가 없다. 다른 PC·시크릿 창에서는 다시 안읽음이며 남에게 전달되지 않는다 |
| 알림 단위 | 알림 = **과업 파일의 최종 변경**이지 상태 전이 이력이 아니다. 키가 `과업번호@최종변경시각` 이라 같은 과업이 또 바뀌면 새 알림으로 다시 안읽음이 된다. 상위 12건만 보이고 밀려난 것은 사라진다 |
